02 / THE DEVELOPER EXPERIENCE

One client.
Your next idea.

Choose a model, send a message, and work with a shared response type. Keep credentials in environment variables and configuration in your own files.

See runnable examples →

Rust 1.96+ · Edition 2024 · Tokio
Build from source; not yet published to crates.io.

examples/chat.rs
use llm_unify::{ChatRequest, Client};

let client = Client::from_env()?;
let model = std::env::var("LLM_UNIFY_MODEL")?;

let response = client.chat(
    ChatRequest::new(model)
        .system("You are a helpful assistant.")
        .user("What will you build next?")
        .max_output_tokens(1024)
).await?;

println!("{}", response.output_text());

04 / GET STARTED

Your gateway.
Up and running.

Clone the repository, configure your upstream, and start with Docker Compose.

Full installation & operations guide ↗
1

Get the source

git clone {{repository_url}}.git
cd llm-unify
2

Configure your environment

cp deploy/.env.example deploy/.env

Set the master key, upstream URL, and upstream key in deploy/.env. Set your model in deploy/proxy.yaml.

3

Start the gateway

docker compose --env-file deploy/.env \
  -f deploy/compose.yaml up -d --build

Open the console at 127.0.0.1:4000/ui/ with the default settings. Images are built from source.

i

PROJECT STATUS

Open source. Still evolving.

The proxy console displays configuration. Per-user virtual keys, budget enforcement, usage summaries, and model editing through the UI are not yet available. The proxy uses a shared master key and is not a multi-tenant authorization or billing system. Full LiteLLM OSS parity and product acceptance remain incomplete.

A separate llm-unify-gateway command provides an OpenAI-compatible HTTP relay with a SQLite usage ledger. It is distinct from llm-unify-proxy.
